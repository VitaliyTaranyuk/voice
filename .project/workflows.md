# Рабочие процессы

## Цикл задачи

1. Анализ и декомпозиция
2. Ветка от актуального `main` (`feature/*`, `fix/*`, `refactor/*`, `docs/*`)
3. Реализация
4. Локальные проверки: формат → линтер → сборка → тесты модуля → смежные тесты
5. Commit + Push
6. Pull Request
7. Merge — только после явного подтверждения пользователя

## Именование веток

| Префикс | Назначение |
| --- | --- |
| `feature/` | новая функциональность |
| `fix/` | исправление дефекта |
| `refactor/` | рефакторинг без смены поведения |
| `docs/` | документация |
| `chore/` | инфраструктура, конфиги, зависимости |

## Коммиты

- Небольшие, логически завершённые
- Сообщение описывает *зачем*, а не только *что*
- После успешных проверок Cursor может коммитить и пушить автоматически

## Pull Request

Перед созданием PR:

- нет конфликтов с `main`
- build и тесты зелёные
- описание содержит краткое summary изменений

## Merge и запреты

- Merge только по явной команде пользователя
- Без разрешения запрещены: force push, rebase опубликованных веток, `reset --hard`, удаление веток/тегов, переписывание истории
